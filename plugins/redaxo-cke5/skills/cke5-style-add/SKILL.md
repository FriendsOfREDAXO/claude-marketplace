# CKE5 – Adding a Custom Style

A CKE5 style consists of three parts that must stay in sync:

1. **Frontend CSS** – the class rendered in the published page
2. **Editor preview CSS** – the same class scoped into the CKE5 iframe so editors see the result live
3. **DB entry in `rex_cke5_styles`** – registers the style and its element/class with CKE5

## Step 1 – Frontend CSS

Add the class to your project's stylesheet (typically `assets/styles/_typo.scss` or similar):

```scss
.my-style {
  /* visual properties */
}
```

Build the stylesheet afterwards (`gulp styles` or your project's build command).

## Step 2 – Editor preview CSS

CKE5 reads from `redaxo/src/addons/cke5/custom_data/custom-styles.css`. Add the same rule scoped to the editor container so it appears correctly in the backend:

```css
.ck.ck-editor__editable_inline .my-style {
  /* same properties as frontend */
}
```

> **Note**: `css_definition` in the DB entry (step 3) generates `autogenerated-custom-styles.css` via `Cke5CssHandler::regenerateCssFile()`. That file is overwritten on every save. Put editor styles in `custom-styles.css` for stability; use `css_definition` only when you want the DB to be the single source of truth.

## Step 3 – DB entry

Insert into `rex_cke5_styles` via `rex_sql`:

```php
$sql = rex_sql::factory();
$sql->setTable('rex_cke5_styles');
$sql->setValue('name', 'My Style');       // label shown in the editor toolbar
$sql->setValue('element', 'span');        // HTML element: 'span' = inline, 'p'/'div' = block
$sql->setValue('classes', 'my-style');    // CSS class(es), space-separated if multiple
$sql->setValue('css', '1');              // '1' = provide inline CSS definition, '' = class only
$sql->setValue('css_definition', '.my-style { /* ... */ }'); // written to autogenerated CSS
$sql->setValue('css_path', '');          // alternative: path to a CSS file
$sql->insert();
```

Or via a direct SQL statement (e.g. in a setup script):

```sql
INSERT INTO rex_cke5_styles (name, element, classes, css, css_definition, css_path)
VALUES ('My Style', 'span', 'my-style', '1', '.my-style { /* ... */ }', '');
```

## Step 4 – Activate in the CKE5 profile

**Pitfall**: the Styles section in the profile form is hidden by default — it only appears once `style` is listed in the profile's Toolbar field.

1. CKE5 → Profiles → Edit the relevant profile
2. Add `style` as a tag in the **Toolbar** field → the Styles section appears below
3. Select the new style in the multi-select list
4. Save

## Element choices

| `element` | Result |
|---|---|
| `span` | Inline style — applied to a text selection |
| `p` | Block style — applied to the whole paragraph |
| `div` | Block style — wraps content in a `<div>` |

A `span` with `display: block` behaves visually like a block but stays applicable as an inline style in CKE5 — useful for eyebrow patterns inside headings.

## Common pitfalls

- **Style not selectable**: `style` is missing from the profile toolbar. Add it first; the Styles multi-select only appears afterwards.
- **Editor doesn't show the style visually**: the class is in the frontend CSS but not in `custom-styles.css`. The editor iframe only loads CKE5's own CSS plus the files in `custom_data/`.
- **Changes lost after CKE5 update**: `autogenerated-custom-styles.css` is regenerated from DB on each save — edits to that file directly are lost. Use `custom-styles.css` for persistent editor styles.
- **Multiple classes**: put them space-separated in the `classes` field, e.g. `'highlight bold'`. CKE5 applies all of them to the element.
